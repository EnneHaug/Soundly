# Phase 9 — UI Design Contract

> Visual and interaction contract for the **Custom Composer modal** (`Composer.tsx`,
> `SegmentRow.tsx`, `StepperInput.tsx`, `SoundPicker.tsx`), the **Custom dashboard
> entry** (`CustomCard.tsx`), and the **Toast** affordance shared by share-success
> and share-decode-error flows. Generated by gsd-ui-researcher; will be verified
> by gsd-ui-checker.

**Inheritance posture.** Phase 9 inherits Phase 3 + Phase 8's entire 6-pillar
contract verbatim (warm earth palette, spacing scale, typography roles, button
class strings, 80 px / 44 px touch targets, `prefers-reduced-motion` gate). It
adds **zero new design tokens**, adds **two new CSS keyframes blocks**
(`dialog-backdrop-in`, `dialog-in`), and adopts the **dashed-border** visual
variant exclusively on `CustomCard` to differentiate "create" from "preset start".
Every visual decision below traces to a CONTEXT D-01..D-21 locked decision or a
RESEARCH Pattern recommendation; **Claude's Discretion (UI)** entries cover only
the gaps the upstream artifacts deliberately left open.

### SoundPicker pill color contract (D-04 + D-05 LOCKED)

```ts
// Verbatim — used in SoundPicker.tsx
const PILL_SELECTED_BG: Record<'gentle' | 'triangle' | 'alarm', string> = {
  gentle:   'bg-sage text-white',
  triangle: 'bg-sand text-text-primary',  // sand is light — primary text reads better than white
  alarm:    'bg-accent text-white',
};

// Unselected pill: stroked outline on bg with secondary text;
// hover/focus tints background at ~10% of the would-be selected color.
const PILL_UNSELECTED =
  'bg-bg border border-border text-text-secondary ' +
  'hover:bg-[color-mix(in_srgb,var(--pill-tint)_10%,transparent)] ' +
  'focus-visible:bg-[color-mix(in_srgb,var(--pill-tint)_10%,transparent)]';
// `--pill-tint` is set per-pill via inline style: sage / sand / accent.
```

**Why `triangle` selected uses `text-text-primary` instead of `text-white`.**
Sand `#c8b89a` is a light tone; white text on sand drops below the contrast floor
for the small `text-sm` pill label. Primary text `#3d4a38` on sand renders at
~7:1 (well above WCAG AA 4.5:1). **Claude's Discretion (UI)** confirmed by
luminance check — sage and accent both have low enough luminance that white text
clears 4.5:1.

| Property | PresetCard | CustomCard |
|----------|------------|------------|
| Border | `border border-border` (solid, 1px) | `border-2 border-dashed border-border` (dashed, 2px — slightly heavier so the dash pattern reads at small sizes) |

### 60/30/10 + Accent reserved-for list

- **Dominant 60%** — `--color-bg` page + modal background; CustomCard surface
- **Secondary 30%** — `bg-white/60` Cancel/Share button surface; SegmentRow neutral state
- **Accent 10%** — RESTRICTED to: (1) Start button `bg-accent`; (2) selected-alarm SoundPicker pill `bg-accent`; (3) invalid-row border `border-accent/50`. **NOTHING ELSE.** The `+ Add segment` button, the `⧉` Duplicate icon, the `×` Delete icon, the modal title, and the Total display MUST NOT use `bg-accent` or `text-accent`.

**Destructive color contract.** Phase 9 has one technically-destructive action:
**segment Delete**. Per D-12 LOCKED, delete is **instant** and **uses the same
neutral `×` glyph** as the close-X — *not* an accent-colored / red treatment. The
zen-UX-friction-free philosophy treats deletion as cheap-and-reversible (re-add
via `+ Add segment`), so the visual affordance intentionally stays calm. **No
destructive token added.** This is consistent with Phase 8's "Stop is recovery,
not destruction" rule.

| State | Copy / Behavior |
|-------|-----------------|
| Empty segment list (N=0) | **Cannot occur.** Per D-12 LOCKED, the Delete button on the last remaining segment is disabled. The composer always has N ≥ 1 segments. Pre-loaded default = Wake Easy template (5 segments). |
| Invalid composition (N ≥ 1 but `validateSegmentConfig` rejects) | Start disabled with tooltip `Fix invalid segments first`. Offending row(s) get the `border-accent/50` accent-tinted outline. ### Destructive actions

**One destructive action: segment Delete.** Per D-12 LOCKED, delete is instant
(no confirmation modal) because the zen-UX-friction-free philosophy treats
deletion as cheap-and-reversible — the user can re-add via `+ Add segment` and
Duplicate. The disabled-when-last-remaining rule (`At least one segment required`
tooltip) is the safety floor — the composer never reaches zero segments.

**No confirmation dialogs in Phase 9.** Stop/Start/Share/Cancel/Delete/Duplicate
all execute immediately. Cancel returning to Dashboard discards in-progress
edits silently (per CONTEXT "no cache across Cancel → reopen" Claude's Discretion).

## Visual Hierarchy

Top-to-bottom inside the Composer modal:

1. **Modal title `Custom alarm`** (`text-xl font-semibold`) — anchors the user
   in "you are editing, not running"
2. **Total display `Total: 17:00`** (`text-3xl font-light tabular-nums`) — the
   single largest element on the screen because total-time is the most
   information-dense feedback for "is my composition the length I want?"
3. **SegmentRow list** (scrollable) — equal-weight rows; the eye scans top-to-
   bottom; each row's duration display is `text-lg` so individual segments
   subordinate to the Total
4. **`+ Add segment` button** — bottom of the list, before the footer; spatially
   continuous with the list it extends
5. **Footer buttons** (sticky) — `Cancel | Share | ... | Start` — Start is
   visually heaviest (filled accent), Cancel + Share are equal-weight outlined
   secondaries on the left

**Single-glance hierarchy contract.** A user glancing at the composer for less
than 500 ms must read, in order: "Custom alarm" (where am I), "Total: 17:00"
(how long is this), "Start" (how do I commit). Per-row editing is intentionally
secondary — it's task-mode, not glance-mode.

### StepperInput layout

Verbatim layout for `StepperInput.tsx`:

```tsx
<div className="inline-flex items-center gap-2">
  <button
    type="button"
    onClick={onDecrement}
    aria-label="Decrease duration"
    className="w-11 h-11 rounded-full border border-border bg-white/60 text-text-primary text-xl leading-none flex items-center justify-center active:scale-[0.95] transition-transform hover:bg-white/80 disabled:opacity-40 disabled:cursor-not-allowed"
  >−</button>
  <input
    type="number"
    inputMode="none"   /* suppress mobile keypad — RESEARCH Pattern 3 */
    readOnly           /* edits go through +/- buttons + arrow keys only */
    value={formatMmSs(valueMs)}
    aria-label="Segment duration"
    aria-invalid={isInvalid}
    onKeyDown={handleStepperKeyDown}  /* ArrowUp/Down/PageUp/Down/Shift+Arrow per D-02 */
    className="w-20 text-center text-lg text-text-primary bg-transparent border-0 focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-sage/40 rounded"
    style={{ fontVariantNumeric: 'tabular-nums' }}
  />
  <button
    type="button"
    onClick={onIncrement}
    aria-label="Increase duration"
    className="w-11 h-11 rounded-full border border-border bg-white/60 text-text-primary text-xl leading-none flex items-center justify-center active:scale-[0.95] transition-transform hover:bg-white/80 disabled:opacity-40 disabled:cursor-not-allowed"
  >+</button>
</div>
```

**Key decisions:**
- Circular buttons (`rounded-full`) to differentiate from the rounded-xl footer buttons (different role: stepper increment vs primary action)
- `bg-white/60` matches the secondary surface tone (not accent — these are utility increments, not the primary "Start" CTA)
- `text-xl` on the `+/−` glyphs balances visually against `text-lg` on the duration text
- `readOnly + inputMode="none"` keeps screen-reader semantics from `<input type="number">` while suppressing the mobile numeric keypad (which would conflict with the +/- gesture model)
- `aria-invalid` propagates the row's invalid state to the input for assistive tech

### SoundPicker layout

Verbatim layout for `SoundPicker.tsx` (RESEARCH Pattern 4 — `role="radiogroup"` + roving tabindex):

```tsx
<div
  role="radiogroup"
  aria-label="End-of-segment sound"
  className="inline-flex items-stretch rounded-xl border border-border bg-bg p-1 gap-1"
>

    const isSelected = value === sound;
    const tint = sound === 'gentle' ? 'var(--color-sage)'
               : sound === 'triangle' ? 'var(--color-sand)'
               : 'var(--color-accent)';
    return (
      <button
        key={sound}
        type="button"
        role="radio"
        aria-checked={isSelected}
        tabIndex={isSelected ? 0 : -1}            /* roving tabindex */
        onClick={() => onChange(sound)}
        onKeyDown={handlePickerKeyDown}            /* ArrowLeft/Right/Enter/Space per D-07 */
        style={{ ['--pill-tint' as never]: tint }}
        className={
          'flex-1 min-h-[44px] px-4 py-2 rounded-lg text-sm transition-colors ' +
          (isSelected
            ? (sound === 'triangle'
                ? 'bg-sand text-text-primary font-semibold'
                : sound === 'gentle'
                  ? 'bg-sage text-white font-semibold'
                  : 'bg-accent text-white font-semibold')
            : 'bg-transparent text-text-secondary hover:bg-[color-mix(in_srgb,var(--pill-tint)_10%,transparent)] focus-visible:bg-[color-mix(in_srgb,var(--pill-tint)_10%,transparent)]')
        }
      >
        {sound === 'gentle' ? 'Gentle' : sound === 'triangle' ? 'Triangle' : 'Alarm'}
      </button>
    );
  })}
</div>
```

**Container** is a single rounded-xl outline (1 px border) with internal 4 px
padding holding three flex-1 children — this gives the classic "segmented control"
visual where the selected pill sits flush inside the outline.

### Toast layout (shared component)

Verbatim layout for `Toast.tsx`:

```tsx
<div
  role="status"            /* RESEARCH Pattern 11 — polite live region for calm UX, not assertive */
  aria-live="polite"
  aria-atomic="true"
  className={
    'fixed left-1/2 -translate-x-1/2 bottom-8 z-50 ' +
    'px-4 py-3 rounded-xl bg-text-primary/95 text-bg text-sm shadow-lg ' +
    'max-w-[calc(100vw-2rem)] text-center ' +
    'transition-opacity duration-200 ' +
    (visible ? 'opacity-100' : 'opacity-0 pointer-events-none')
  }
>
  {message}
</div>
```

**Auto-dismiss timings (LOCKED):**
- Share success: **3 s** (D-19)
- Share rejection: **4 s** (longer because the message asks the user to take a follow-up action)
- Decode failure: **4 s** (D-18)

**Why `role="status"` + `aria-live="polite"` (not `aria-live="assertive"`).**
A calm zen aesthetic demands non-interrupting affordances. `polite` waits for
the screen reader's current utterance to finish before announcing; `assertive`
would interrupt mid-sentence. Toasts here are informational, never urgent —
errors are recoverable (try-the-address-bar fallback) and decode-failure already
landed the user safely on the default template.

**Why fixed-position bottom-center.** Doesn't overlap the modal header
(top-anchored title) nor the footer buttons (the Start tooltip caption lives
just under the footer when disabled). On desktop the modal occupies max-w-md
centered; the toast slides under the modal's lower edge. On mobile it sits
above the safe-area-inset-bottom (the `bottom-8` value ≈ 32 px is far enough
from the home-indicator strip).

## Animations

### 1. Modal open animation (D-15 LOCKED)

Verbatim CSS to append to `src/index.css` (after the Phase 8 `pulse-active-arc` block):

```css
/* Phase 9: Composer modal scrim + open animation (D-15) */
dialog::backdrop {
  background: rgba(61, 74, 56, 0.4);   /* --color-text-primary at 40% alpha */
  opacity: 0;
  animation: dialog-backdrop-in 200ms ease-out forwards;
}

dialog[open] {
  opacity: 0;
  transform: translateY(16px);
  animation: dialog-in 240ms ease-out forwards;
}

@keyframes dialog-backdrop-in {
  to { opacity: 1; }
}
@keyframes dialog-in {
  to { opacity: 1; transform: translateY(0); }
}

@media (prefers-reduced-motion: reduce) {
  dialog::backdrop {
    animation-duration: 100ms;
  }
  dialog[open] {
    transform: none;
    animation: dialog-in-reduced 100ms ease-out forwards;
  }
  @keyframes dialog-in-reduced {
    from { opacity: 0; }
    to   { opacity: 1; }
  }
}
```

**Decisions encoded:**
- Scrim: text-primary at 40% alpha (sage-greenish dark wash that visually anchors the warm earth palette behind it — the Dashboard still reads through, preventing disorientation)
- Slide: 16 px upward over 240 ms ease-out (matches D-15 LOCKED values exactly)
- Fade: 200 ms ease-out on scrim (matches D-15 LOCKED)
- **Reduced-motion gate:** scrim fade shortened to 100 ms; modal slide REPLACED with pure opacity fade (no transform); both per D-15 LOCKED. The reduced-motion `@keyframes dialog-in-reduced` explicitly starts at `opacity: 0` because removing the `transform` rule means the original `dialog-in` keyframe's `transform: translateY(0)` becomes a no-op transition.

### 2. Modal close animation

`<dialog>.close()` does NOT animate the modal out by default — the element
disappears immediately when its `open` attribute is removed. **Claude's Discretion (UI):**
**Phase 9 ships without a close-out animation.** Rationale:

1. CSS transitions on disappearing elements require either `:has(...)` selectors (poor cross-browser support in 2026 still) or JS-driven className toggling with a timeout — adding complexity for an animation that only plays during dismissal.
2. The Phase 8 reduced-motion-gate pattern already prioritizes "static end states are sufficient affordances" — dismissal is a state change the user actively triggered (Cancel / X / Escape / browser-back), not something they need feedback continuity for.
3. The modal-in animation is the affordance that the modal opens *from* the Dashboard; the inverse is implicit in the immediate disappearance.

If a future UX audit requires close-out animation, the pattern would be:
className toggle on `dialog[open]` → `dialog[data-closing="true"]` for 200 ms,
then call `dialog.close()` in the `transitionend` handler. Out of scope for Phase 9.

### 3. Per-row invalid-border transition

```tsx
// SegmentRow gains/loses the border-accent/50 outline as validity flips
<div className={`... transition-colors duration-200 ${isInvalid ? 'border border-accent/50 rounded-lg' : ''}`}>
```

`transition-colors duration-200` smooths the appearance/disappearance of the
accent outline as the user adjusts the duration in/out of validity. Not gated
behind reduced-motion — it's a color transition, below the threshold reduced-
motion users object to (the rule is movement, not color fades).

### 4. Toast fade

`transition-opacity duration-200` on the Toast root element. Same rationale as
the row-invalid transition — opacity is not motion. Not gated behind reduced-motion.

### 5. Pulse / scale on button tap

All buttons inherit `active:scale-[0.98]` (or `active:scale-[0.95]` on the
smaller stepper buttons). This is the existing v1 idiom; matches Phase 3 D-09.
Not gated behind reduced-motion (the existing v1 code does not gate it either —
Phase 9 does not retroactively add gating to inherited animations, since the
scale transform is below the perception threshold most reduced-motion users
object to).

- CustomCard: `min-h-[80px]` — exceeds minimum (matches v1 PresetCard)

### Focus order

Composer modal — default DOM order = visual order:

1. Close-X (header right) — tab 1
2. Stepper of SegmentRow 1: `−`, input, `+` — tabs 2, 3, 4

5. Delete of SegmentRow 1 — tab 7
6. ... (same pattern for rows 2..N) ...
7. `+ Add segment` button
8. Cancel
9. Share
10. Start

**Why close-X is tab 1:** Most-common dismissal action; users entering the
modal via keyboard should be able to escape without tabbing through every row.

**Focus trap:** Free — provided by native `<dialog>.showModal()` (RESEARCH Pattern 1).

**Focus on open:** The browser focuses the first focusable element in the dialog
by default (the close-X). Per RESEARCH Pattern 1 footnote, no custom autofocus
override needed.

### Screen reader

- Modal: `<dialog aria-labelledby="composer-title">` + `<h2 id="composer-title">Custom alarm</h2>` — SR announces "Custom alarm dialog" on open
- Stepper input: `<input aria-label="Segment duration" aria-invalid={isInvalid}>` — SR announces value changes as the user steps
- Stepper buttons: `aria-label="Decrease duration"` / `"Increase duration"` — SR reads action verb
- SoundPicker: `<div role="radiogroup" aria-label="End-of-segment sound">` containing three `<button role="radio" aria-checked>` — SR announces "End-of-segment sound, radio group, three options"; arrow-key navigation announces each pill on focus
- Duplicate / Delete: `aria-label="Duplicate segment"` / `"Delete segment"` — SR reads action

- Start disabled: `disabled` attribute → implicit `aria-disabled="true"`; tooltip text via `title=` is read by some SRs and ignored by others; the mobile caption below the button covers the gap

### Hash decode privacy

Per D-18 LOCKED: hash is cleared via `history.replaceState(null, '', location.pathname + location.search)` immediately after decode (success or failure). This prevents:
- Refresh re-triggering composer auto-open
- Accidental social-share of the URL with the shared-composition still in it
- Browser history showing the shared composition's hash

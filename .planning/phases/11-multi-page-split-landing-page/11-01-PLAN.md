<derived_decisions>

## D-LAND-17 (NEW — derived from RESEARCH Finding 4)

**Add `manifest.id: '/Soundly/'` to the PWA manifest.**

**Rationale:** Without an explicit `manifest.id`, browsers use `start_url` (resolved against the manifest's origin) as the implicit identity. When `start_url` changes from `/Soundly/` (Phase 10) to `/Soundly/app/` (Phase 11), the browser may treat the new manifest as a **different application** — installed v1.0/v2.0 users could end up with a stuck old PWA pointing at the (now-rewritten) landing, while the new manifest registers as an "uninstalled" candidate.

**Value choice — `/Soundly/`:** Matches the Phase 10 installed `start_url`; safest for migration of existing installs. Per RESEARCH Q6 recommendation — "Use `id: '/Soundly/'` — URL-form, maximizes Chrome/Edge compatibility, preserves continuity with v1's implicit identity."

**This is a one-way ratchet.** Once `id` is set and shipped, changing it in the future is itself a breaking install-identity change. Document prominently in code comment.

</derived_decisions>

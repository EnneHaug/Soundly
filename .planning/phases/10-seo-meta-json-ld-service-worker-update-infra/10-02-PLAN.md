<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public/robots.txt → web crawlers | Crawlers honor Allow/Disallow directives. Listing private paths in robots.txt is itself a disclosure (Pitfall: "security through robots.txt" is anti-pattern). |
| public/sitemap.xml → Google Search Console | Anyone can read the sitemap. Listing internal-only URLs there leaks structure. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-02-01 | Information Disclosure | robots.txt | mitigate | robots.txt lists NO private paths (Soundly has none — verified: no admin route, no auth, no `/internal/*`). `Allow: /` is intentionally permissive. |
| T-10-02-02 | Information Disclosure | sitemap.xml | accept | The two URLs (`/` and `/app/`) are both public landing surfaces. `/app/` is forward-compat for Phase 11; until it exists it 404s — not a leak. No private surface enumerated. |
| T-10-02-03 | Tampering | sitemap.xml XML structure | mitigate | Automated verifier asserts well-formedness (XML decl + namespace + 2 `<loc>` entries with exact values). Plan 06 adds DOMParser test. |
| T-10-02-04 | Spoofing | Sitemap URL ownership | accept | Search Console verifies domain ownership before accepting a sitemap submission. Anyone with the same placeholder string in their own deploy would only submit their own domain's sitemap. |
| T-10-02-05 | Denial of Service | sitemap.xml hand-edits | mitigate | XML well-formedness asserted by Plan 06 test; bumping `<lastmod>` is a regex-safe edit documented in deploy runbook. |
| T-10-02-06 | Repudiation | sitemap.xml content | accept | Git history is sufficient audit trail. |
</threat_model>

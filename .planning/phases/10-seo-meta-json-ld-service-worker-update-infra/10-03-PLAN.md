<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Service worker → all clients in scope | `skipWaiting()` + `clientsClaim()` cause the new SW to take over EVERY client in scope without user consent. Scope here = `/Soundly/` (project base). Affects all tabs/windows of the installed PWA. |
| New SW → installed PWA user | The new SW serves freshly-cached HTML on next navigation. If the new SW has a bug, users get the buggy version without an "update" prompt. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-03-01 | Tampering | SW lifecycle | mitigate | Both `skipWaiting()` + `clientsClaim()` are workbox-canonical idioms; the workbox-core helper handles the "claim before activation" exception. No custom lifecycle logic — fewer custom-code surface points to attack. |
| T-10-03-02 | Elevation of Privilege | SW scope expansion | mitigate | SW scope is unchanged at `/Soundly/` (vite-plugin-pwa default = same as base). `skipWaiting` + `clientsClaim` do NOT widen scope; they only accelerate takeover within the existing scope. Phase 11 will rescope SW to `/app` only — this plan doesn't touch scope. |
| T-10-03-03 | Denial of Service | buggy new SW silently overrides | accept | D-18 LOCKED silent update — no user prompt before takeover. Mitigation: deploy runbook (Plan 05) documents the post-deploy smoke test (build v1 → install → deploy v2 → reopen → confirm v2 meta). Solo-dev project; user OWNS the trust decision. Acceptable risk vs. the alternative (stale meta forever). |
| T-10-03-04 | Information Disclosure | SW cache contents | accept | SW caches only the manifest-listed precache assets + the navigation fallback (`/Soundly/index.html`). No PII, no secrets — Soundly has zero persistent storage (PROJECT.md). |
| T-10-03-05 | Repudiation | SW source edits | accept | Git history audit. |
| T-10-03-06 | Spoofing | replaced SW via MITM | mitigate | HTTPS-only deploy (GitHub Pages enforces). SW registration requires HTTPS (browser-enforced for non-localhost). |
</threat_model>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTML source → social scrapers | OG/Twitter/iMessage/Slack bots fetch the static HTML; whatever appears in `<meta>` becomes the shared-card payload. Untrusted consumers cannot inject; but malformed HTML here could break previews for ALL shared links. |
| JSON-LD `<script>` block → HTML parser | The `<script type="application/ld+json">` content is HTML-parsed (not JSON-parsed) at the tokenization step. A `</script>` substring inside the JSON content terminates the script element prematurely. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-01-01 | Tampering | JSON-LD `<script>` block | mitigate | Locked copy (D-12) contains NO `</script>` substring; deploy runbook (Plan 05) documents the maintenance rule "never include literal `</script>` in JSON-LD; escape as `<\/script>`". Pitfall 4. |
| T-10-01-02 | Information Disclosure | placeholder canonical URL | accept | `https://soundly.local/Soundly/` is a known-fake placeholder, not a real internal domain. No PII / no internal hostname leaked. Deploy runbook documents pre-publish swap. |
| T-10-01-03 | Spoofing | OG image URL | mitigate | `og:image` points to the same origin (`https://soundly.local/Soundly/og-image-v1.png`); cross-origin scrapers cannot substitute. Image content approved by user (D-09) before commit. |
| T-10-01-04 | Repudiation | meta block edits | accept | Single-author solo project; git history is sufficient audit trail. |
| T-10-01-05 | Denial of Service | malformed HTML | mitigate | Automated verifier (above) regex-checks all required tags + JSON.parse on JSON-LD; build verification gate in Plan 06 confirms `dist/index.html` ships correctly. |
| T-10-01-06 | Elevation of Privilege | JSON-LD content | accept | Schema.org JSON-LD does not execute; static data only. No script-eval path. |
</threat_model>

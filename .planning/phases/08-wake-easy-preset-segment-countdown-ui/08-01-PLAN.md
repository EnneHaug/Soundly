**Append exactly these lines to the end of `src/index.css`** (verbatim from UI-SPEC L390-401):

```css

/* Phase 8: Segment-mode active-arc pulse during firing-alarm (D-03, D-04) */
@keyframes pulse-active-arc {
  0%, 100% { opacity: 1; }
  50%      { opacity: 0.7; }
}

@media (prefers-reduced-motion: no-preference) {
  .pulse-active {
    animation: pulse-active-arc 1s ease-in-out infinite;
  }
}
```

Note the leading blank line — separates the new block from the existing `}` closing the `@theme` declaration.

Do NOT modify any line above the existing closing `}` of `@theme`. The existing palette tokens (`--color-bg`, `--color-text-primary`, ..., `--font-size-countdown`) MUST remain byte-identical.

**Why this exact shape:**
- `0%, 100% { opacity: 1; }` + `50% { opacity: 0.7; }` produces a 1.0 → 0.7 → 1.0 cycle over 1 second (D-04 "1Hz" + UI-SPEC L411-414).
- `ease-in-out infinite` gives a "breathing" feel rather than a strobe (UI-SPEC L414).
- `@media (prefers-reduced-motion: no-preference)` gates the animation behind the user NOT having a reduce-motion preference (UI-SPEC L405-409, RESEARCH Pitfall 7). Users with reduce-motion preferences see static opacity 1.0 — the firing-alarm state is still indicated by the static segment-5 position + count-up timer + "Wake" label.

**Why opacity, not stroke color** (UI-SPEC L416-418): Pulsing the color would require a second accent token. Opacity preserves the single-token palette and pulses on the same color the eye is already tracking.

# Phase 8 — UI Design Contract

> Visual and interaction contract for the Wake Easy preset card and the new
> N-segment countdown screen. Phase 8 is a thin UI layer over the already-shipped
> SegmentEngine + WAKE_EASY_CONFIG. Almost every visual primitive Phase 8 needs
> already exists in v1; this contract captures how the new components reuse them.
> Generated by gsd-ui-researcher; will be verified by gsd-ui-checker.

**Inheritance posture.** Phase 8 inherits Phase 3's design conventions verbatim
(03-CONTEXT D-04 warm earth palette, D-06 ring shape, D-07 large mm:ss, D-08
phase label, D-09 Stop/Pause control row, D-13 80px touch target). It does NOT
introduce a new design system; it adds two new components (`SegmentCountdown`,
`SegmentProgressRing`), one card label, and one CSS keyframes block.

### Arc-state opacity contract (D-02 + D-19 LOCKED)

| Arc state | Stroke | Opacity | Notes |
|-----------|--------|---------|-------|
| Track (always rendered behind every arc) | `var(--color-faded)` | `0.4` | Same idiom as `ProgressRing.tsx:114-124` |
| Past (already fired) | `var(--color-faded)` | `0.6` | Mirrors `ProgressRing.tsx:128-139` |
| Current — running, not paused | `SOUND_COLORS[endSound]` | `1.0` | Width clipped to remaining portion via `arcPath(start, start + remainingArc)` |
| Current — paused (D-19) | `SOUND_COLORS[endSound]` | `0.5` | Frozen at snapshot position; opacity drop is the freeze affordance |
| Current — firing-alarm (D-03) | `SOUND_COLORS['alarm']` | pulses `1.0 ↔ 0.7` at 1 Hz | See "Animations" section |
| Future (not yet started) | `SOUND_COLORS[endSound]` | `1.0` | Mirrors `ProgressRing.tsx:155-166` |

**60/30/10 rationale.** The page background (`--color-bg`) is the dominant tone.
Card and button surfaces (`bg-white/60`) sit at 30% as soft elevation cues over
the warm bg. Terracotta accent (`--color-accent`) is rationed strictly to the
Stop button + the alarm arc — these are the two "action / urgency" signals in
the phase. Sage and sand are ARC-ONLY decorative tokens; they don't compete with
accent because they never appear on interactive surfaces.

**Destructive color:** Phase 8 has no destructive actions. **Stop is recovery,
not destruction** — it returns the user to a safe Dashboard state, no data loss.
Stop reuses the accent color (terracotta) as a high-attention "this ends the alarm"
signal, matching `Countdown.tsx:147` byte-for-byte. No new destructive token added.

**Accent reserved for:** (1) Stop button background `bg-accent`; (2) the alarm
segment arc when its `endSound === 'alarm'`; (3) NOTHING else. The "4 x 4" card,
the Pause/Resume button, the segment label, the total caption, and all gentle/triangle
arcs MUST NOT use `bg-accent` or `text-accent`.

**Contrast (D-04 inheritance).** All text colors retain Phase 3's contrast ratios
verified against the bg. No Phase 8 introduces new text-on-color combinations.
The pulse animation drops opacity to 0.7 (not below) — at 0.7 against `--color-bg`,
the alarm arc remains clearly visible.

## Visual Hierarchy

Top-to-bottom on the SegmentCountdown screen:

1. **Ring** (max-width 280px, full visual focus) — the single dominant element on
   the screen, taking ~280px square in the center.
2. **Big timer** (centered inside the ring, `var(--font-size-countdown)`) — primary
   glance target. Says "how long until the next event."
3. **Total-time caption** (small, secondary text below big timer, inside the ring)
   — tells the engaged user how much total time is left across the whole composition.
4. **Phase label** (small secondary text, last line inside the ring) —
   `Segment X of N — {soundLabel}`. Tells the user "where am I in the sequence."
5. **Control row** (40px below the ring) — `Pause`/`Resume` (left, ghost) and
   `Stop` (right, accent). Stop is intentionally heavier-weight per `Countdown.tsx`
   accent treatment.

**Single-glance hierarchy contract.** A user glancing at the screen for less than
500ms must read, in order: how much time until the next chime (big number), then
which segment they're in (label below). The total-time caption is intentionally
tertiary — it answers "is this almost over?" but never competes with the primary
glance.

### Pause-state opacity transition

**Claude's Discretion (UI):** the active arc opacity change between `1.0` (running)
and `0.5` (paused) uses a **200ms ease-out CSS transition on the SVG `<path>` `opacity`
attribute** rather than a hard switch. Rationale: matches the "subtle" aesthetic
target of Phase 3 D-10 ("Phase transitions are subtle") and aligns with the
existing `transition-opacity duration-500` on the phase label at `Countdown.tsx:129`.
A transition of 500ms felt sluggish for a state change that the user actively
triggered (pause-button tap), so 200ms is the chosen split-the-difference value.

```tsx
// SVG path for the current-arc, paused dimming variant
<path
  className="transition-opacity duration-200"
  // ... d, stroke, strokeWidth, strokeLinecap as usual
  opacity={pausedDimming ? 0.5 : 1}
/>
```

## Animations

### 1Hz pulse on firing-alarm active arc (D-03 / D-04 LOCKED)

Per D-04, the pulse is implemented in **pure CSS keyframes**. JS-driven animation
is explicitly NOT used. **Claude's Discretion:** keyframes live in `src/index.css`
appended after the existing `@theme` block (currently 18 lines; this addition
brings it to ~28 lines) — single global location, easy to find, no per-component
`<style>` blocks, no Tailwind config edit needed.

**Verbatim CSS to append to `src/index.css`:**

```css
/* Phase 8: Segment-mode active-arc pulse during firing-alarm (D-03, D-04) */
@keyframes pulse-active-arc {
  0%, 100% { opacity: 1; }
  50%      { opacity: 0.7; }
}

@media (prefers-reduced-motion: no-preference) {
  .pulse-active {
    animation: pulse-active-arc 1s ease-in-out infinite;
  }
}
```

**Reduced-motion handling.** The pulse rule is wrapped in
`@media (prefers-reduced-motion: no-preference)` — animation only fires when the
user has NOT expressed a preference for reduced motion. Users with motion
sensitivity preferences see the active arc at static opacity 1.0; the firing-alarm
state is still indicated by the segment-5 pinned position + the count-up timer +
the "Wake" label, so the pulse is not the sole signal.

**Why this keyframe shape (1.0 ↔ 0.7).** D-04 calls out 0.7 ↔ 1.0; the keyframe
above uses `0%, 100% { opacity: 1; }` and `50% { opacity: 0.7; }` so the cycle
goes 1.0 → 0.7 → 1.0 over a 1-second period (`ease-in-out`), giving a gentle "still
firing, breathing" feel rather than a strobe.

**Why opacity, not stroke color.** Pulsing the color (e.g., between two accent
shades) would require declaring a second accent token; opacity preserves the
single-token palette and pulses on the same color the eye is already tracking.

**Application site.** The `.pulse-active` class is conditionally applied to the
current-arc `<path>` element in `SegmentProgressRing` only when
`pulseActive === true` (which the parent component sets when
`alarm.state === 'firing-alarm'`):

```tsx
<path
  className={pulseActive ? 'pulse-active' : undefined}
  // ... d, stroke, strokeWidth, strokeLinecap as usual
  opacity={pausedDimming ? 0.5 : 1}
/>
```

Note: `pausedDimming` and `pulseActive` are mutually exclusive in practice — per
Pitfall 4 in 08-RESEARCH, `engine.canPause()` returns false during firing-alarm,
so `isPaused` is guaranteed false when `state === 'firing-alarm'`. The component
does not need to handle "pulse + dim" simultaneously.

### Pause/resume opacity transition (Claude's Discretion — already covered above)

200ms ease-out on `<path>` opacity. See Interaction States section.

### Phase-label crossfade (inherited from v1)

The `Segment X of N — {soundLabel}` label inherits `transition-opacity duration-500`
from `Countdown.tsx:129`. When the label text changes (e.g., segment 1 ends and
segment 2 starts), React re-renders with new text; the existing transition is sufficient
visual continuity. Phase 8 adds no new label animation logic.

### NO segment-end "flash" animation

A subtle bloom on a just-completed arc was discussed (08-CONTEXT deferred ideas)
but explicitly **out of scope for Phase 8**. The chime sound IS the segment-end
signal; visual flash is a future enhancement.

## Accessibility

### Touch targets

- "4 x 4" PresetCard: `min-h-[80px]` (inherited from `PresetCard.tsx:20`) — exceeds
  WCAG 2.5.5 minimum 44×44px and Apple HIG 44pt recommendation.
- Pause/Resume button: `px-8 py-3` (≈ 64px wide × ≈ 44px tall) — meets minimum.
  This is the existing v1 button geometry; Phase 8 does not change it.
- Stop button: same as Pause/Resume — meets minimum.

### Focus order

The SegmentCountdown screen has only two focusable elements: Pause/Resume, then
Stop. Default DOM order = visual order (Pause left, Stop right) — no `tabindex`
overrides needed. The Dashboard adds the "4 x 4" card to the existing focus order
after Quick Nap, after Focus, and before TestSoundButton — natural reading order.

### Disabled affordance

Pause button during firing-alarm: `disabled={true}` + `opacity-40 cursor-not-allowed`
gives both ARIA-implicit signaling (browsers expose `aria-disabled` for native `disabled`
attribute) and visible affordance. The button does not become invisible — preserving
spatial muscle memory for users who might glance to where Pause "should be."

### Reduced motion

- Pulse animation: gated behind `@media (prefers-reduced-motion: no-preference)`
  per the keyframes block above. Users with reduce-motion preferences see a static
  active arc; firing-alarm is still indicated by position, count-up timer, and label.
- Pause-state opacity transition (200ms ease-out): NOT gated. A 200ms opacity fade is below
  the threshold most reduced-motion users object to (the rule of thumb is to gate
  movement, not subtle fades). The static end-state difference (1.0 vs 0.5) carries
  the affordance regardless of whether the transition runs.
- Phase-label crossfade (500ms inherited from v1): same — opacity-only, 500ms
  is the existing v1 idiom and no v1 reduce-motion handling exists in `Countdown.tsx`.
  Phase 8 does not retroactively add reduce-motion handling to inherited animations
  (would touch `Countdown.tsx` — protected by SEG-05).

### Color contrast

All text-on-background pairings inherit from Phase 3 D-04 and have not changed.
The two new Phase 8 visual primitives — the pulse 0.7 opacity floor and the
paused 0.5 opacity floor — were chosen specifically not to drop below the
text-readability threshold for the small-caption sizes used in the ring center.
The big timer never gains opacity treatment (only ring arcs do); it remains at
opacity 1.0 in all states.

### Screen reader

- Big mm:ss timer: rendered as plain text inside `<span>` — screen readers will
  announce successive values as the timer ticks (a known noisy behavior in v1
  `Countdown.tsx`; not addressed in Phase 8 to preserve byte-identical posture).
- Phase label `Segment X of N — Gentle chime`: meaningful as plain text; readable
  by screen readers without ARIA additions.
- SVG ring: `<svg role="img" aria-label="Alarm progress">` (inherited from
  `ProgressRing.tsx:191-194`). Phase 8's `SegmentProgressRing` MUST emit the same
  attributes (planner: copy these attribute names verbatim onto the new `<svg>`).
- Pause / Stop buttons: plain `<button>` elements with text content — fully
  accessible by default.

## Responsive Behavior

### Breakpoints

Phase 8 ships **only the mobile-portrait viewport** as the design target, matching
v1.0's PWA-mobile-first focus. Mobile = the design baseline; desktop renders the
same layout centered.

Phase 8 introduces NO new breakpoints. The existing `max-w-md` (28rem ≈ 448px)
constrains the wrapper width on desktop; on mobile, `w-full` + `px-6` gives natural
edge padding. The ring's `max-w-[280px]` keeps it from growing oversized on tablets.

| Viewport | Behavior |
|----------|----------|
| 320–448px (mobile portrait) | Wrapper = full width; ring fills 280px max within the wrapper; cards stack vertically |
| 448–1024px (tablet, desktop) | Wrapper centered at 448px; ring still capped at 280px; same layout, more whitespace |
| > 1024px | Same as tablet — Phase 8 does NOT use responsive utilities to reflow into a multi-column desktop layout |

### Type scale

a 768px tablet ≈ 5rem; on a 1024px desktop ≈ 5rem (capped). No additional Phase 8
adjustments needed.

### Ring size

`max-w-[280px]` from `ProgressRing.tsx:189` — `SegmentProgressRing` reuses the
exact same wrapper class string per the verbatim copy in 08-RESEARCH Pattern 4.

### Orientation

Portrait-native per CLAUDE.md `orientation: "portrait"`. Phase 8 does not test
landscape rendering; the `flex flex-col` + `max-w-md` wrapper gracefully degrades
to landscape but the ring + controls + label may extend below the viewport on
short landscape phones. Acceptable — this is a portrait-locked PWA.
